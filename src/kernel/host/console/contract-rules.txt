================================================================
AEVUM BOOT 契约规则文档
版本: v4
范围: boot.asm 引导程序职责、字段归属、失败报告、交接约定
方针: 归属唯一、失败可见
================================================================


一、核心方针
----------------------------------------------------------------
1. 归属唯一:  每个字段有且只有一个写者职责,读者可多,写者唯一.
2. 失败可见:  每个可能失败的步骤必须打印一条可见消息,
              不再分配 0xRRFFTT 数字错误码.
3. 字段是职责的产物; 失败消息是字段违约的产物.
4. 必须性与值有效性依赖必须显式声明,不允许沉默假设.


二、职责清单
----------------------------------------------------------------
ID   职责名                          唯一执行位置
R1   读盘加载 stage2                 实模式, int 0x13 前后
R2   建立临时 GDT                    保护模式前, lgdt
R3   切换到保护模式                   cr0.PE + 远跳转, 只一次
R4   建立初始页表                    保护模式后, 开分页前
R5   开启分页                        cr3 + cr0.PG, 只一次
R6   设置交接栈                      保护模式后, 跳转前
R7   交接跳转到 stage2               唯一交接点, 写 boot info
R9   A20 状态声明                    实模式, R3 之前

职责不重复: R10/R11 已并入 R7, 交接职责唯一.
每个职责只在自己的位置执行, 不在别处补写.


三、字段归属表
----------------------------------------------------------------
字段                                    唯一写者  必须性
R1_READ_DISK_STAGE2_SECTORS_READ        R1        MANDATORY
R2_BUILD_GDT_PHYS                       R2        MANDATORY
R2_BUILD_GDT_LIMIT                      R2        MANDATORY
R2_BUILD_GDT_TEMPORARY                  R2        MANDATORY
R3_ENTER_PM_ENABLED                     R3        MANDATORY
R4_BUILD_PAGETABLE_PD_PHYS              R4        MANDATORY
R4_BUILD_PAGETABLE_PT0_PHYS             R4        MANDATORY
R4_BUILD_PAGETABLE_MAPPED_BYTES         R4        MANDATORY
R5_ENABLE_PAGING_ENABLED                R5        MANDATORY
R6_SETUP_STACK_TOP                      R6        MANDATORY
R6_SETUP_STACK_LIMIT                    R6        MANDATORY
R7_HANDOFF_STAGE2_ENTRY                 R7        MANDATORY
R7_HANDOFF_IDT_READY                    R7        MANDATORY
R7_HANDOFF_REGS_STATE_MASK              R7        DEGRADABLE
R9_A20_STATE_VALUE                      R9        MANDATORY


四、值有效性依赖
----------------------------------------------------------------
写入时机规则 (本节对所有字段生效):
  字段必须在对应职责动作之前写入, 不得事后补写.
  R2 的 GDT 字段必须在 lgdt 之前写入;
  lgdt 之后补写的字段视为记录失真, 违反本节.

字段                                    值有效性依赖
R1_READ_DISK_STAGE2_SECTORS_READ        int 0x13 返回的 AL, 不得假设读满
R2_BUILD_GDT_PHYS/LIMIT                 0x7C00 附近未被覆盖; 且先于 lgdt 写入
R2_BUILD_GDT_TEMPORARY                  恒为 1, 声明失效点; 先于 lgdt 写入
R3_ENTER_PM_ENABLED                     远跳转已完成
R4_BUILD_PAGETABLE_*                    内核不得占用 0x10000/0x11000
R5_ENABLE_PAGING_ENABLED                远跳转已完成
R6_SETUP_STACK_TOP/LIMIT                stage2 必须尽快切换栈
R7_HANDOFF_STAGE2_ENTRY                 stage2 镜像已就位
R7_HANDOFF_IDT_READY                    恒为 0, 声明未建立
R7_HANDOFF_REGS_STATE_MASK              声明哪些寄存器有效
R9_A20_STATE_VALUE                      检测结果, 非假设


五、失败报告规则
----------------------------------------------------------------
不再分配 0xRRFFTT 数字错误码。

boot 失败:
  BIOS teletype 打印一行可见消息, 然后 cli; hlt.
stage2 失败:
  VGA 打印 "[ERR] <字段消息>", 然后 cli; hlt.

定位信息 = 失败阶段 + 消息文本; 不写内存错误块, 不需要解码表.
R2-R7、R9 目前只写成功字段, 不伪造失败消息; 需要时再补真实检测.


六、失败消息表
----------------------------------------------------------------
阶段   消息                              触发
R1     AEVUM boot: disk read failed       int 0x13 进位
R1     AEVUM boot: stage2 short read      实读扇区数 < 声明
R10    stage2 entry mismatch              R7 入口不是 0x1000
R10    mapped bytes mismatch              R4 映射字节不是 0x400000
R11    vga init failed                    VGA 回写测试失败
R15    serial init failed                 串口回环测试失败


七、交接约定
----------------------------------------------------------------
交接点: R7, 唯一交接职责.
交接内容: boot info 块, 基址 0x0500.
交接方式: 远跳转到 R7_HANDOFF_STAGE2_ENTRY.
交接时状态:
  - 保护模式已开
  - 分页已开, 仅映射 0~4MB 恒等映射
  - 中断关闭
  - IDT 未建立 (R7_HANDOFF_IDT_READY = 0)
  - 临时 GDT 位于 0x7C00 附近
  - 栈顶 0x7C00, 上限 0x7000

临时 GDT 失效点:
  stage2 重建 GDT 并重载 CS/DS/ES/SS 之后,
  0x7C00 附近才可被覆盖.


八、沉默契约清单(待补)
----------------------------------------------------------------
P0  A20 状态: R9 写 NOT_TESTED, 内核必须自己检测或重试.
P0  IDT 未建立: R7 声明 IDT_READY=0, 内核必须自建 IDT 后再开中断.
P0  仅映射 4MB: R4 写 MAPPED_BYTES, 内核访问 4MB 以上前必须扩展映射.
P1  页表区占用: 0x10000/0x11000 不得被内核占用.
P1  stage2 大小: 构建期检查 <= 16 扇区, 超限构建失败.
P2  栈上限: 0x7000, stage2 应尽快切换自己的栈.


九、扩展规则
----------------------------------------------------------------
1. 加字段:  先在职责表里确认唯一写者, 再在字段表加一行,
            再在失败消息表加对应消息, 最后改 boot info 布局.
2. 升版本:  boot info 头部加 magic + version,
            内核先验 magic/version 再决定兼容策略.
3. 加职责:  先确认是否与现有职责重复, 重复则并入,
            不重复才新增 R 号.
4. 改布局:  常量集中定义, 不在代码里出现裸数值做字段.


十、C 语言补充规则
----------------------------------------------------------------
10.1 失败返回约定
  函数返回 const char *:
    0 表示成功.
    非 0 是失败字段名字面量, 例如 "entry" / "stack" / "slot" / "state".
  owner 由失败点的上层填写; field 直接使用返回值.
  失败点必须填 type/detail/at; 禁止再把数字码当唯一身份.
  跨模块调用失败时:
    下层返回失败字段, 上层保留该字段并补 at,
    不重新打包, 不层层套娃.
  type 字符串固定为:
    "missing" / "conflict" / "dependency" / "external" / "state"

10.2 头文件契约规则
  契约头 (可被跨模块 include) 只放:
    - 类型定义 (含不透明句柄 struct xxx;)
    - 函数声明
  契约头禁止放:
    - 结构体字段布局 (boot info 除外, 跨阶段共享数据)
    - static inline 实现
    - 任何平台头 (stdio.h / windows.h / pthread.h)
  实现头 (只允许本模块 .c include) 可放结构体布局.

10.3 链接可见性规则
  字段写者函数: static 或模块内可见, 不导出.
  字段读者函数: 可导出, 命名带 _read / _get 后缀, 语义只读.
  跨模块符号: 统一 aevum_ 前缀, 显式 visibility,
              禁止 extern 裸变量.


十一、错误日志格式
----------------------------------------------------------------
11.1 成功基线 (不打错误码, 只打字段值)
  [aevum] boot ok
    R1 stage2_sectors_read = 16
    R2 gdt phys=0x7C00 limit=23 temporary=1
    R3 pm_enabled = 1
    R4 mapped_bytes = 0x400000
    R5 paging_enabled = 1
    R6 stack top=0x7C00 limit=0x7000
    R7 stage2_entry = 0x1000  idt_ready = 0
    R9 a20_state = NOT_TESTED
    -> jump stage2

11.2 失败块 (统一五行)
  [aevum][ERR]
    owner   : 模块名
    field   : 失败字段名
    type    : missing / conflict / dependency / external / state
    detail  : 具体原因 (期望值 / 实际值)
    at      : 源码位置

11.3 失败示例
  [aevum][ERR]
    owner   : arm_app
    field   : task_create(control)
    type    : dependency
    detail  : arm app task assembly failed
    at      : kernel_main -> arm_app_init

11.4 禁止的日志形式
  - 只打一句自然语言 ("R7 failed while calling external dependency")
  - 只打数字码不打字段
  - 同一个 field 覆盖多个不同失败点
  - 丢 at, 无法定位到调用点
  - 层层套娃把最内层失败字段包丢
