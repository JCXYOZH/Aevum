================================================================
AEVUM BOOT 契约规则文档
版本: v1
范围: boot.asm 引导程序职责、字段归属、错误码、交接约定
方针: 归属唯一、定位有码
================================================================


一、核心方针
----------------------------------------------------------------
1. 归属唯一:  每个字段有且只有一个写者职责,读者可多,写者唯一.
2. 定位有码:  每个可能失败的步骤有唯一阶段 ID,
              错误码 = (职责 ID << 16) | (字段 ID << 8) | 错误类型.
3. 字段是职责的产物,错误码是字段的产物.
4. 必须性与值有效性依赖必须显式声明,不允许沉默假设.


二、职责清单
----------------------------------------------------------------
ID   职责名                          唯一执行位置
R1   读盘加载 stage2                 实模式, int 0x13 前后
R2   建立临时 GDT                    保护模式前, lgdt
R3   切换到保护模式                   cr0.PE + 远跳转, 只一次
R4   建立初始页表                    保护模式后, 开分页前
R5   开启分页                        cr3 + cr0.PG, 只一次
R6   设置交接栈                      保护模式后, 跳转前
R7   交接跳转到 stage2               唯一交接点, 写 boot info
R8   失败汇聚与报告                  唯一失败汇聚, 双入口 _rm/_pm
R9   A20 状态声明                    实模式, R3 之前

职责不重复: R10/R11 已并入 R7, 交接职责唯一.
每个职责只在自己的位置执行, 不在别处补写.

R8 双入口说明:
  R8_rm: 实模式失败汇聚入口 (16 位指令)
  R8_pm: 保护模式失败汇聚入口 (32 位指令)
  两个入口写入同一组 R8 字段, 数据布局完全相同,
  职责仍唯一归属于 R8; 入口数增加不改变职责归属.
  实模式失败跳 R8_rm, 保护模式失败跳 R8_pm, 不得交叉跳转.

四、值有效性依赖
----------------------------------------------------------------
写入时机规则 (本节对所有字段生效):
  字段必须在对应职责动作之前写入, 不得事后补写.
  R2 的 GDT 字段必须在 lgdt 之前写入;
  lgdt 之后补写的字段视为记录失真, 违反本节.

字段                                    值有效性依赖
R1_READ_DISK_STAGE2_SECTORS_READ        int 0x13 返回的 AL, 不得假设读满
R1_READ_DISK_ERROR_CODE                 仅失败时有效
R2_BUILD_GDT_PHYS/LIMIT                 0x7C00 附近未被覆盖; 且先于 lgdt 写入
R2_BUILD_GDT_TEMPORARY                  恒为 1, 声明失效点; 先于 lgdt 写入
R3_ENTER_PM_ENABLED                     远跳转已完成
R4_BUILD_PAGETABLE_*                    内核不得占用 0x10000/0x11000
R5_ENABLE_PAGING_ENABLED                远跳转已完成
R6_SETUP_STACK_TOP/LIMIT                stage2 必须尽快切换栈
R7_HANDOFF_STAGE2_ENTRY                 stage2 镜像已就位
R7_HANDOFF_IDT_READY                    恒为 0, 声明未建立
R7_HANDOFF_REGS_STATE_MASK              声明哪些寄存器有效
R8_FAIL_REPORT_*                        仅失败时有效
R9_A20_STATE_VALUE                      检测结果, 非假设


五、错误码规则
----------------------------------------------------------------
格式: 0xRRFFTT
  RR = 职责 ID (R1=0x01 ... R9=0x09)
  FF = 职责内字段 ID (从 0x00 起)
  TT = 错误类型

错误类型:
  0x01 = 字段缺失
  0x02 = 字段冲突(第二个写者出现)
  0x03 = 值有效性依赖未满足
  0x04 = 外部操作失败(BIOS/硬件/跨模块依赖)

定位方式:
  读 R8_FAIL_REPORT_ERROR_CODE
  -> 拆出 RR, 查职责表得职责
  -> 拆出 FF, 查字段表得字段
  -> 拆出 TT, 得违约类型

七、交接约定
----------------------------------------------------------------
交接点: R7, 唯一交接职责.
交接内容: boot info 块, 基址 0x0500.
交接方式: 远跳转到 R7_HANDOFF_STAGE2_ENTRY.
交接时状态:
  - 保护模式已开
  - 分页已开, 仅映射 0~4MB 恒等映射
  - 中断关闭
  - IDT 未建立 (R7_HANDOFF_IDT_READY = 0)
  - 临时 GDT 位于 0x7C00 附近
  - 栈顶 0x7C00, 上限 0x7000

临时 GDT 失效点:
  stage2 重建 GDT 并重载 CS/DS/ES/SS 之后,
  0x7C00 附近才可被覆盖.


八、沉默契约清单(待补)
----------------------------------------------------------------
P0  A20 状态: R9 写 NOT_TESTED, 内核必须自己检测或重试.
P0  IDT 未建立: R7 声明 IDT_READY=0, 内核必须自建 IDT 后再开中断.
P0  仅映射 4MB: R4 写 MAPPED_BYTES, 内核访问 4MB 以上前必须扩展映射.
P1  页表区占用: 0x10000/0x11000 不得被内核占用.
P1  stage2 大小: 构建期检查 <= 16 扇区, 超限构建失败.
P2  栈上限: 0x7000, stage2 应尽快切换自己的栈.


九、扩展规则
----------------------------------------------------------------
1. 加字段:  先在职责表里确认唯一写者, 再在字段表加一行,
            再在错误码表加对应码, 最后改 boot info 布局.
2. 升版本:  boot info 头部加 magic + version,
            内核先验 magic/version 再决定兼容策略.
3. 加职责:  先确认是否与现有职责重复, 重复则并入,
            不重复才新增 R 号.
4. 改布局:  常量集中定义, 不在代码里出现裸数值做字段.


十、C 语言补充规则
----------------------------------------------------------------
10.1 错误返回约定
  函数返回 uint32_t, 值即 0xRRFFTT.
  0x00000000 表示成功.
  RR 段填本函数自身职责号, 不填调用方, 也不填上游.
  跨模块调用失败时:
    返回值 = (本职责 << 16) | (本字段 << 8) | 0x04
    同时写入依赖明细:
      dep_rr   = 上游职责号
      dep_code = 上游原始 0xRRFFTT (最内层, 不重包)
  依赖明细与返回值分离, 不占用 0xRRFFTT 的位.
  包装只包一层: 本函数写自己的 RR 和 0x04,
  明细保留最内层上游码, 不层层套娃.
  依赖明细的实现方式由各模块决定 (模块错误槽或出参),
  但必须满足: 调用方失败后能读回 dep_rr 和 dep_code.
  TT=0x04 用于: 硬件/驱动/BIOS 失败, 以及跨模块依赖调用失败.

10.2 头文件契约规则
  契约头 (可被跨模块 include) 只放:
    - 类型定义 (含不透明句柄 struct xxx;)
    - 错误码常量 (0xRRFFTT)
    - 函数声明
  契约头禁止放:
    - 结构体字段布局 (boot info 除外, 跨阶段共享数据)
    - static inline 实现
    - 任何平台头 (stdio.h / windows.h / pthread.h)
  实现头 (只允许本模块 .c include) 可放结构体布局.

10.3 链接可见性规则
  字段写者函数: static 或模块内可见, 不导出.
  字段读者函数: 可导出, 命名带 _read / _get 后缀, 语义只读.
  跨模块符号: 统一 aevum_ 前缀, 显式 visibility,
              禁止 extern 裸变量.


十一、错误日志格式
----------------------------------------------------------------
11.1 成功基线 (不打错误码, 只打字段值)
  [aevum] boot ok
    R1 stage2_sectors_read = 16
    R2 gdt phys=0x7C00 limit=23 temporary=1
    R3 pm_enabled = 1
    R4 mapped_bytes = 0x400000
    R5 paging_enabled = 1
    R6 stack top=0x7C00 limit=0x7000
    R7 stage2_entry = 0x1000  idt_ready = 0
    R9 a20_state = NOT_TESTED
    -> jump stage2

11.2 失败块 (统一四行 + 可选明细)
  [aevum][ERR] 0xRRFFTT
    owner   : R? / 职责名
    field   : 字段名
    type    : 0xTT 类型说明
    detail  : 具体原因 (外部码 / 期望值 / 实际值)
    at      : 源码位置

11.3 单层依赖失败 (RR 填本函数, 明细带上游)
  [aevum][ERR] 0x070004
    owner   : R7 / HANDOFF
    field   : STAGE2_ENTRY
    type    : 0x04 外部依赖失败
    detail  : dep=R2, dep_code=0x020003
              dep_owner : R2 / BUILD_GDT
              dep_field : GDT_PHYS
              dep_type  : 0x03 依赖未满足
              reason    : gdt phys region overwritten
    at      : boot.asm R7_handoff

11.4 多层依赖链 (只包一层, 明细带 root_dep)
  [aevum][ERR] 0x410004
    owner   : K / kernel_init
    field   : BOOT_HANDOFF
    type    : 0x04 外部依赖失败
    detail  : dep=R7, dep_code=0x070004
              dep_owner : R7 / HANDOFF
              dep_field : STAGE2_ENTRY
              dep_type  : 0x04 外部依赖失败
              root_dep  : dep=R2, dep_code=0x020003
                          R2 / BUILD_GDT / GDT_PHYS / 0x03 依赖未满足
    at      : kernel/init.c:127

11.5 字段冲突 (TT=0x02)
  [aevum][ERR] 0x040002
    owner   : R4 / BUILD_PAGETABLE
    field   : PD_PHYS
    type    : 0x02 字段冲突
    detail  : expected_writer=R4
              actual_writer=R7
              addr=0x10000
    at      : registry/claim.c:44

11.6 字段缺失 (TT=0x01)
  [aevum][ERR] 0x090001
    owner   : R9 / A20_STATE
    field   : A20_STATE_VALUE
    type    : 0x01 字段缺失
    detail  : mandatory field has no writer
              policy  : kernel must detect or retry
    at      : boot.asm R9

11.7 日志必含四要素 (按顺序)
  1. 归属码 0xRRFFTT
  2. owner (职责名) + field (字段名)
  3. type (TT 说明)
  4. detail + at (定位信息)

11.8 禁止的日志形式
  - 只打一句自然语言 ("R7 failed while calling external dependency")
  - 只打 RR 不打 FF/TT
  - 丢失 dep_code 只留 "dependency failed"
  - 层层套娃把原始码包丢

11.9 R8 双入口日志等价性
  R8_rm 与 R8_pm 写入的字段完全相同,
  日志读取字段时不区分入口.
  日志中 at 字段由汇编手工写入, 用于区分入口:
    R8_rm 失败 -> at = "boot.asm R8_rm"
    R8_pm 失败 -> at = "boot.asm R8_pm"
  除 at 外, 两种入口的日志块结构完全一致.
