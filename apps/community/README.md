# 社区平台 · apps/community

社区自己的平台本体。目标形态：**一份 Web 前端**，既能挂在自己的服务器上访问，也能被桌面端打包带走，多窗口，并带真实的工作能力（社区工具按需调度、本地安装、内置更新）。

当前只走到第一层：静态站。没有服务端，没有账号，没有发帖。

## 目录

```
apps/community/
├── README.md
└── web/            前端 Web，现在就是整站
    ├── index.html  单文件自包含：CSS 与 JS 都内联，无依赖、无构建
    └── assets/     图片资源（二维码放这里）
```

`desktop/` 目录尚未创建。桌面端计划是给 `web/` 套壳，而不是另写一套界面——同一份 HTML，两个壳。

## 本地预览

```powershell
cd D:\Aevum\apps\community\web
python -m http.server 8080
```

打开 `http://localhost:8080`。

直接双击 `index.html` 也能看，但 `file://` 下复制邮箱按钮的剪贴板权限和二维码的相对路径表现与 HTTP 环境不同，验收请用上面的方式。

## 放到服务器

静态站没有构建步骤，`web/` 目录本身就是发布产物：

1. 服务器上克隆仓库；
2. nginx 的 `root` 指向 `apps/community/web`；
3. 更新时 `git pull`，刷新即生效——不需要重新打包、不需要重启服务。

具体的安全基线与证书配置写在 `docs/guides/deployment.md`（待补）。

## 二维码

把图片存成 `web/assets/qrcode.png`，页面会自动替换掉占位框，不需要改代码。

- 正方形，短边 ≥ 256px；
- 留白边（扫码识别需要静区）；
- 建议命名固定为 `qrcode.png`，换群只换图。

## 现状与限制

- 单文件、零依赖、无 JS 框架；只有一段复制邮箱的脚本和一个二维码兜底。
- 移动端优先书写样式，768px 以上展开为双栏。
- 没有深色模式，没有多语言切换。
- 页面里的进度数字是写死的（2026-11-08 口径），改动时同步 `PROGRESS.md`。
